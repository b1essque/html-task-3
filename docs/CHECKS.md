# Контрольные сценарии

Основная проверка: актуальный Chrome/Chromium, область страницы **1280 × 1000 CSS-пикселей**, масштаб 100%, CPU без ограничения, Network: No throttling. В DevTools Device Toolbar выберите Responsive и задайте размер. Сервер уже управляет задержками; дополнительное ограничение сети для основной серии не требуется.

Используйте одинаковый браузер и настройки для исходной и исправленной версии. На вкладке Network включайте Preserve log только при необходимости, чтобы не смешивать загрузки разных сценариев.

## 1. Холодная и повторная загрузка

Для каждого `normal`, `slow`, `race`, `reverse`:

1. Откройте DevTools → Network, включите **Disable cache** и перезагрузите страницу. Запишите результат до и после завершения запросов.
2. Дождитесь загрузки ресурсов и шрифта. В Console можно выполнить `await document.fonts.ready`.
3. Убедитесь, что Console не содержит ошибок приложения. Нажмите «Компактно», затем «Подробно».
4. Снимите **Disable cache**. Один раз перезагрузите страницу, чтобы заполнить кеш, и дождитесь ресурсов. Затем выполните обычную перезагрузку ещё раз — это проверка прогретого кеша. Network должен показать использование memory/disk cache там, где оно доступно.
5. Повторите проверку кнопок, консоли и количества инициализаций. Не используйте Hard reload в этом шаге.

Проверочные выражения, которые не изменяют страницу:

```js
document.querySelectorAll('#news-feed .news-card').length // 1000
document.querySelector('#news-feed').dataset.initCount   // "1"
document.querySelector('#news-feed').dataset.view        // "compact" или "detailed"
Boolean(window.newsAnalytics?.loaded)                   // true после загрузки статистики
```

После одного клика должна появляться одна новая запись `news:view-change` в `performance.getEntriesByName('news:view-change')`. Количество обработчиков нельзя исправлять только изменением этого счётчика или скрытием записей.

## 2. Первое отображение и скачки

1. Включите Disable cache и откройте `/?scenario=slow` с начала страницы.
2. Запишите загрузку в Performance с включёнными Screenshots.
3. На ленте кадров должен быть момент, когда заголовок и вводный текст уже читаются, а запросы иллюстрации и статистики ещё не завершены. Подтвердите его по времени запросов в Network/Performance.
4. Сравните положение `#lead-title`, `.lead-intro`, `.archive-toolbar` и первой `.news-card` в первом кадре с читаемым текстом и после загрузки ресурсов. Их границы не должны смещаться более чем на 1 CSS-пиксель при неизменном размере окна. Изменение формы букв при загрузке шрифта само по себе не считается сдвигом блока.
5. Проверьте эту же последовательность в режиме `reverse`, где иллюстрация загружается раньше шрифта.

Во время этого измерения не прокручивайте страницу, не изменяйте размер окна и не переключайте вид. Не добивайтесь стабильности обрезанием текста или ожиданием всех ресурсов перед показом страницы.

## 3. Структура описаний

В Elements выберите любую карточку. У неё должны быть собственные заголовок, полное описание, метаданные и ссылка. Все три части описания должны быть потомками одной `.story-summary`.

```js
const cards = [...document.querySelectorAll('.news-card')];
cards.every(card => ['.summary-lead', '.summary-details', '.summary-ending']
  .every(selector => card.querySelector('.story-summary')
    ?.contains(card.querySelector(selector)))) // true
```

В режиме «Компактно» ни одна из трёх частей описания не видна. В режиме «Подробно» видны все три. После переключений количество карточек и текстов в DOM не меняется.

## 4. Пять замеров Layout

Сохраните исходную версию до редактирования или запустите её отдельно из тега `starter`:

```sh
git worktree add --detach ../html-task-3-starter starter
cd ../html-task-3-starter
PORT=4174 npm start
```

В PowerShell последняя команда: `$env:PORT=4174; npm start`. Если в исправленном проекте меняется порт, применяйте одинаковый сценарий на обоих адресах.

Для каждой версии выполните пять независимых прогонов:

1. Откройте `/?scenario=normal`, дождитесь `load` и `document.fonts.ready`. Исходный вид — «Подробно».
2. Прокрутите страницу так, чтобы кнопки выбора вида были видны. Не меняйте размер окна.
3. В Performance отключите Screenshots для этой серии и начните запись.
4. Один раз нажмите «Компактно». Дождитесь смены вида и следующего кадра, остановите запись.
5. Выберите интервал **всего клика**, от начала первого обработчика до первого кадра с готовым компактным видом. В исходной версии один клик может вызывать несколько обработчиков: их нельзя исключать из замера.
6. В Bottom-up найдите **Layout** и запишите сумму Self time этих событий в выбранном интервале. Если версия DevTools иначе группирует события, укажите это в отчёте. Не подменяйте время Layout общей длительностью `news:view-change`.
7. Для следующего прогона перезагрузите страницу и повторите шаги. Сохраните записи, а не только цифры.

Отсортируйте пять значений и возьмите третье — медиану. Условие: **медиана Layout исправленной версии ≤ половины медианы исходной**. Это сравнение на одном устройстве, а не требование к абсолютному времени.

Отключите расширения, создающие дополнительную нагрузку, и закройте тяжёлые фоновые вкладки. Зафиксируйте одинаковые условия в отчёте.
